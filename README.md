# SignAdapt

**Personalized federated learning for signer-adaptive isolated sign language recognition.**

Sign language recognition models degrade on signers they were not trained on. SignAdapt
measures that gap, then tests whether a *federatedly-trained shared encoder plus a private
per-signer classifier head* closes it with fewer local examples than a signer training
alone — with raw video never leaving the device.

The specification is [`PLAN.md`](PLAN.md); it is authoritative. This README only says how to
run things.

## Two data caveats found in phase 1

Both are measured, not suspected. Numbers below come from
`results/phase1-extraction_lsa64_*.json`, regenerated by `make data`.

### 1. The fluorescent gloves defeat the hand landmarker

LSA64's subjects wear fluorescent gloves, which the dataset authors added to make hand
segmentation easy for classical computer vision. For a modern learned hand landmarker they do
the opposite: a gloved hand is a saturated blob with no visible finger boundaries, and
MediaPipe often returns no hand at all. Counting only the hands each sign actually uses
(both hands for the 22 two-handed signs, the dominant hand otherwise):

| | clips | required hands present | clips never complete |
|---|---|---|---|
| one-handed signs | 2100 | 85.1 % of frames | 10 |
| two-handed signs | 1100 | **51.2 %** of frames | 122 |
| all | 3200 | 73.5 % of frames | 132 |

Pose is detected in 100.0 % of frames and face in 99.2 %. Raising the input to native 1080p
and lowering the detector confidence to 0.05 both fail to recover the missing hands, so this
is a property of the data, not a tuning mistake.

Consequences, all handled explicitly rather than papered over:

- Missing hands are `valid = 0` with NaN coordinates, never zero-filled — after anchoring,
  zero *is* the mid-shoulder point, a perfectly plausible hand position.
- Pose landmarks include the wrists, so arm trajectory survives where the hand fails.
- Availability varies **0.625–0.819 across signers** (spread 0.195). Some of the inter-signer
  accuracy variance this thesis reports will therefore be detection quality rather than
  signing style, and the two-handed signs carry most of the damage. This belongs in the
  limitations section.

### 2. LSA64's "signer 10" is two different people

The dataset documents that subject 10 was unavailable for the second recording session and
was replaced; this is plainly visible in the video (a bearded man for signs 1–23, a
long-haired woman for signs 24–64). Signers 3 and 7 were checked and are consistent, so only
signer 10 is affected.

This matters here more than it did for the dataset's original purpose: one client per signer
means client 10 is two people sharing one private classifier head, and the leave-one-signer-out
fold for signer 10 measures generalization to two unseen people at once.

**Decision: keep all 10 signers**, report the signer-10 fold separately, and disclose the
confound. `ClipRecord.participant` returns `"10a"`/`"10b"` where person identity is the
question, and `splits.exclude_signers: [10]` in `configs/data.yaml` switches to 9 clean
clients if that turns out to be preferable later.

## Setup

```bash
python3.12 -m venv .venv
make setup          # pip install -e ".[dev,demo]"
make test
```

Tested on macOS 15 (Apple M4, 16 GB) with Python 3.12.

## Commands

| Command | Does |
|---|---|
| `make data` | Download LSA64, extract and cache MediaPipe keypoints to `.npy` |
| `make train` | Centralized baselines (E1, E2, E6) |
| `make federated` | Flower simulation (E4 FedAvg, E5 FedPer) |
| `make figures` | Rebuild every figure from committed `results/*.json` |
| `make demo` | Webcam → keypoints → caption → virtual camera |
| `make test` | pytest, including the signer-leakage guard |
| `make lint` / `make format` | ruff |

`SEED=1 make train` overrides the seed; `experiments/run_all.sh` runs everything in order.

## Conventions

- **Results are JSON.** Every run writes one self-describing file to `results/` containing its
  config snapshot, seed, environment and git commit. Figures are generated from those files;
  no number is ever typed into a figure by hand.
- **Runs are seeded.** `signadapt.utils.seeding.seed_everything(seed)` fixes python, numpy and
  torch, and records whether deterministic kernels were actually available.
- **Signer disjointness is enforced by a test**, not by convention — `tests/test_splits.py`.
  Signer leakage would invalidate every result in the thesis.

## Ethics and limitations

No Deaf participants were involved in this work. It is a *methodological* study of
personalization and federated adaptation that uses sign language recognition as its task
domain; it is not an assistive product and is not validated with its intended users.
Evaluation uses only public datasets recorded with consent. See `PLAN.md` §3.
